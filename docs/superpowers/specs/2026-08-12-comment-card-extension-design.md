# 「神评卡片」浏览器扩展设计规格 V1

## 1. 文档状态

- 日期：2026-08-12
- 状态：MVP 设计已确认
- 首发平台：B 站网页版视频详情页
- 产品形态：Chrome/Chromium 浏览器扩展（Manifest V3）
- 核心目标：用户在评论区发现内容后，用尽量短的路径生成一张具有收藏感和传播欲的静态评论卡片。

## 2. 产品边界

### 2.1 MVP 包含

- B 站网页版评论识别与手动选择。
- 统一的悬浮入口和选择模式。
- 评论元素的浮起、渐变流光边框和小范围水雾反馈。
- 生成前的最小确认卡：风格、比例、封面开关。
- 四套卡片风格：温暖、历史、嘲讽、SSS 级。
- `3:4` 与 `9:16` 两种导出比例，默认 `3:4`。
- 默认关闭的“游戏化装饰”开关。
- 基于评论与风格种子的稳定趣味属性。
- Canvas 本地渲染与 PNG 下载。

### 2.2 MVP 不包含

- 卡片编辑器或自由排版。
- AI 评论评分、AI 标题、AI 模板推荐。
- 自动选择高赞评论。
- 点赞数、头像、视频标题、回复关系或楼层信息。
- GIF、视频或透明动态素材导出。
- 收藏、排行、分享链接、账号、模板市场或后端服务。
- YouTube、抖音、小红书等其他平台。

以上能力可进入后续路线，但不得成为首版交付依赖。

## 3. 核心用户流程

1. 扩展在 B 站视频详情页加载完成，右下角显示“流光卡片核”悬浮入口。
2. 用户点击入口，页面进入评论选择模式。
3. 页面显示卡片式提示，光标切换为选择光标。
4. 用户悬停合法评论时，评论轻微上浮，外沿显示渐变流光与弱呼吸水雾。
5. 用户点击评论，打开最小确认卡。
6. 用户选择风格、比例及是否使用视频封面，然后确认生成。
7. 确认卡收束成光核，少量粒子聚合成卡片轮廓。
8. Canvas 完成本地渲染并下载 PNG。
9. 页面显示短暂的完成提示，并退出选择模式。

目标体验是从进入选择模式到触发生成只需要一次选取和一次确认。首版不承诺固定“3 秒内完成”，但应以常规设备上无明显等待为性能目标。

## 4. 选择模式交互

### 4.1 进入状态

- 悬浮入口默认安静停驻，仅保留极弱的渐变流动。
- 点击后显示“请选择一条评论”的统一卡片提示。
- 滚轮与触控板滚动不退出选择模式。

### 4.2 评论悬停状态

- 只有适配器确认的评论根元素可被选中。
- 元素轻微上浮，不改变页面布局。
- 边框采用青、紫、粉、暖金的连续渐变流动。
- 水雾仅在边框外沿小范围扩散，呼吸强度低于流光边缘。
- 正文区域不叠加雾化或高亮，确保阅读清晰。

### 4.3 退出状态

以下任一操作立即退出并清理所有临时样式与监听器：

- 按 `Esc`。
- 鼠标右键；选择模式下本次右键不弹出浏览器菜单，退出后恢复正常。
- 点击任意非评论区域。
- 再次点击悬浮入口。
- 点击提示卡中的退出按钮。
- 页面导航、标签页关闭、评论区根节点失效或页面结构重建。

## 5. 生成确认卡

确认卡与悬浮入口使用相同的圆角卡片、渐变光谱和反馈节奏，只提供：

- 评论正文只读预览。
- 风格单选：温暖 / 历史 / 嘲讽 / SSS 级。
- 比例单选：`3:4`（默认）/ `9:16`。
- 视频封面开关；成功抓取时默认开启，失败时关闭并禁用。
- 游戏化装饰开关，默认关闭。**（来自旧方案）**
- 取消按钮。
- 生成卡片按钮。

“游戏化装饰”只控制评级徽记、能量纹路、主题角标及额外装饰粒子，不改变卡片结构、趣味属性或基础风格。关闭时仍保留主题背景、边框纹理和必要光效，但整体更接近简洁评论海报。

确认卡不允许修改评论、昵称、时间、字体、颜色、位置或属性值。

## 6. 卡片信息结构

卡片从上到下包含四个区域：

1. 平台区：B 站 Logo 与平台来源标识，尺寸克制。
2. 媒体区：可选视频封面。其高度根据评论长度在安全范围内自适应，通常占卡片高度的 18%–26%；评论越长，封面越小。关闭封面后，内容区自动扩展且不保留空白占位。**（来自旧方案）**
3. 内容区：评论正文是主要视觉元素；用户昵称和发布时间分别占一行，放在正文区域右下、靠近内边框的位置并右对齐。
4. 属性区：展示“幽默值、温暖值、嘲讽值”三项趣味属性。

MVP 不显示头像、点赞数、视频标题、等级来源、回复关系或 AI 评语。

## 7. 趣味属性系统

- 三项属性范围为 `0–100`。
- 使用“标准化评论正文 + 所选风格 + 属性算法版本号”作为种子。
- 同一评论在相同风格与算法版本下生成的数值一致。
- 更换评论或风格后数值允许变化。
- 至少一项主属性落在 `80–99`，确保卡片具有明确个性。
- 最大值使用约 `1.2×` 字号、主题强调色和轻微静态光效。
- 产品文案统一称其为“趣味属性”，不得暗示为 AI 分析或客观评价。

算法需要版本字段，以免未来升级逻辑后无法解释数值变化。

## 8. 卡片视觉系统

### 8.1 统一原则

- 默认形象是一张具有收藏感的评论卡片，不默认采用游戏化包装。
- 风格由背景、边框纹理、少量装饰元素、字体关系、光效粒子共同构成。
- 装饰不得侵入正文安全区，不使用大量徽章、雕花或高密度粒子。
- 平台区、正文、署名和属性区在所有模板中保持一致的信息层级。
- 字体只使用可合法随扩展分发的字体，并提供系统字体回退。
- 开启“游戏化装饰”后，才叠加评级徽记、能量纹路、主题角标和额外装饰粒子；这些装饰仍不得侵入正文安全区。

### 8.2 四套初始风格

#### 温暖

- 米白、杏色、柔粉。
- 柔和纸张肌理、手绘感细边与暖光微粒。
- 可使用极少量星点或植物线条，不使用成片花朵装饰。

#### 历史

- 深棕、旧金、暗红。
- 旧纸、档案或轻微石刻肌理，配古铜细线边框。
- 印章、年代刻度或卷轴线条只能作为局部点缀。

#### 嘲讽

- 黑白高对比，搭配荧光黄绿或紫色强调。
- 锐利边角、少量错位线条和能量裂纹。
- 保持正文排版稳定，不采用影响阅读的故障闪烁。

#### SSS 级

> 来源标识：本风格作为产品视觉锚点的定位来自旧方案，经讨论后纳入当前设计。

- 黑曜石或深色底，搭配金色与紫色高光。
- SSS 评级徽记、金属或能量边框、稀疏星尘粒子。
- 作为产品的视觉锚点和传播型模板，承担“值得收藏、值得分享”的最高视觉记忆点。
- 游戏化装饰关闭时，以黑曜石背景、金紫细边、SSS 字标和稀疏星尘表达等级；开启后可增加能量纹路、评级徽记和更明显的粒子层。
- 不采用复杂 3D、宝石堆叠或 50–100 粒子的爆炸效果。
- 可在生成反馈中使用一次短促的金色扫光，最终 PNG 保持克制的收藏感。

## 9. 尺寸、排版与导出

- `3:4` 默认画布：`1200 × 1600 px`。
- `9:16` 画布：`1080 × 1920 px`。
- MVP 输出：PNG。
- 封面使用裁切填充，焦点默认居中；无法加载时切换无封面布局。
- 评论正文按可用高度自动换行并逐级缩小字号。
- 达到最小字号仍溢出时，按可见字符截断并显示省略号。
- 中文、英文、数字、Emoji 和混排均不得越过内容安全区。
- 昵称与时间使用显著小于评论正文的字号，并保持两行布局。

## 10. 动画与性能

动画只服务于选择反馈和生成仪式，不进入最终静态 PNG：

- 选择边框：连续渐变流动。
- 选择水雾：小范围、低强度呼吸扩散。
- 评论悬停：轻微上浮。
- 生成过程：确认卡收束为光核，少量粒子聚合为卡片轮廓。
- SSS 级：允许一次短促扫光或小规模粒子散射。

选择反馈优先使用 CSS `transform`、`opacity`、渐变和滤镜；生成粒子使用轻量 Canvas。粒子数量应按视觉需要控制在约 12–30 个。系统启用“减少动态效果”时，改用淡入和静态高亮。

## 11. 技术架构

### 11.1 方案选择

采用“Content Script + Shadow DOM 交互层 + Canvas 渲染”方案：

- 不引入首版卡片编辑器。
- 不依赖后端。
- 不以 HTML 截图作为核心导出方式。
- 不为 MVP 强制引入 React、Tailwind、Framer Motion 或 `html2canvas`。

这样可以减少 B 站样式污染、字体渲染差异、跨域截图问题和依赖体积。

### 11.2 模块边界

- `BilibiliAdapter`：定位评论、提取内容、昵称、时间、封面与平台信息。
- `SelectionController`：管理选择模式、可选元素和退出规则。
- `OverlayRoot`：创建 Shadow DOM，承载入口、提示、确认及状态反馈。
- `ConfirmCard`：收集风格、比例和封面选择。
- `StyleRegistry`：提供四套可序列化的视觉参数，不包含业务逻辑。
- `AttributeGenerator`：根据稳定种子生成趣味属性。
- `TextLayoutEngine`：负责测量、换行、缩放和截断。
- `CardRenderer`：按照模板与布局结果绘制 Canvas。
- `ExportService`：将 Canvas 转换为 PNG 并触发下载。
- `PreferenceStore`：只保存最近使用的风格、比例和封面开关。

### 11.3 数据对象

```ts
interface CommentCardSource {
  platform: "bilibili";
  content: string;
  authorName?: string;
  publishedAt?: string;
  videoCoverUrl?: string;
}

interface GenerateOptions {
  style: "warm" | "history" | "sarcasm" | "sss";
  ratio: "3:4" | "9:16";
  includeCover: boolean;
  gameDecoration: boolean;
}
```

点赞数与视频标题不进入 MVP 数据契约，避免采集未使用的数据。

## 12. 平台适配架构

> 来源标识：统一平台适配器接口来自旧方案，经讨论后纳入当前设计。

- 首版只实现 `BilibiliAdapter`，但业务层只依赖统一的 `PlatformAdapter` 接口。
- 统一接口负责判断当前页面、定位评论根节点、识别可选评论、提取标准化评论数据及读取视频封面。
- 平台选择器、页面结构兼容逻辑和字段回退策略只能存在于各自适配器内，不得泄漏到选择控制器或渲染器。
- 后续增加 YouTube、抖音等平台时，通过新增适配器接入，不修改卡片数据契约和生成流程。

建议接口：

```ts
interface PlatformAdapter {
  readonly platform: CommentCardSource["platform"];
  matches(location: Location): boolean;
  findCommentRoot(): Element | null;
  resolveComment(target: EventTarget | null): Element | null;
  extractComment(element: Element): CommentCardSource | null;
  getVideoCoverUrl(): string | undefined;
}
```

### 12.1 B 站动态页面处理

> 来源标识：有限范围的动态评论监听来自旧方案，经讨论后纳入当前设计。

- `BilibiliAdapter` 将 B 站选择器与业务层隔离，方便页面改版后单独维护。
- `MutationObserver` 仅用于判断评论根容器是否被替换、断开或失效，不登记每条新增评论，也不扫描整个文档树。
- 评论识别在悬停或点击时由 `BilibiliAdapter` 即时完成，并通过事件委托处理，避免为每条评论重复绑定监听器。
- observer 回调需要节流，不遍历全部评论节点。
- 页面发生站内跳转或评论根节点替换时，先销毁旧 observer 和选择状态，再定位新容器并重新初始化。
- 所有注入样式位于 Shadow DOM；对原评论仅挂载最小临时 class，并在退出时清除。

## 13. 隐私、来源与使用边界

- 评论数据只在当前标签页和本地内存中处理，不上传、不建立历史库。
- 卡片必须保留 B 站来源标识与原评论昵称，减少脱离语境传播造成的误认。
- 用户主动选择评论后才开始采集。
- 扩展权限遵循最小化原则，仅申请首发所需的 B 站页面与下载能力。
- 项目上线前需进一步核对 B 站品牌标识使用规范、评论内容传播边界和扩展商店政策；本规格不构成法律意见。

## 14. 异常与降级

- 评论识别失败：显示统一错误卡并允许重新选择。
- 昵称缺失：显示“未知用户”；时间缺失：隐藏时间行并保留布局节奏。
- 封面跨域或加载失败：提示后自动使用无封面布局。
- 字体加载失败：使用预设回退字体继续渲染。
- 文本过长：缩放到最小字号后截断。
- Canvas 或下载失败：保留已渲染结果并提供再次下载。
- DOM 更新使目标失效：取消当前悬停或确认状态，提示重新选择。

错误提示统一使用卡片式 UI，不调用浏览器原生 `alert`。

## 15. 测试与验收

### 15.1 单元测试

- 稳定种子与属性值范围。
- 同评论同风格的一致性。
- 文本测量、换行、缩放与截断。
- 样式注册表与画布尺寸。
- 评论数据标准化与缺失字段处理。

### 15.2 DOM 集成测试

- 模拟 B 站评论结构并提取字段。
- 评论懒加载与容器替换。
- 选择模式进入、悬停、选中和清理。
- `Esc`、右键、非评论区域、入口按钮和退出按钮的退出行为。
- Shadow DOM 不污染宿主页面。

### 15.3 浏览器端到端测试

- 完成“进入选择 → 选择评论 → 确认 → 渲染 → 下载”。
- 四套风格、两种比例和封面开关组合可用。
- 导出尺寸正确，关键字体和资源已加载。
- 中文、英文、Emoji 和长文本不越界。
- 同一评论与风格重复生成的属性值一致。
- 评论区滚动、原有点击和动态加载不被破坏。
- 减少动态效果开启时功能完整。

## 16. 已确认借鉴项

本版本从前期方案中正式吸收以下内容：

- SSS 级作为产品的视觉锚点。**（来自旧方案）**
- 使用统一平台适配接口隔离网站 DOM 差异，首版实现 B 站适配器。**（来自旧方案）**
- 将游戏化包装实现为默认关闭的可选开关。**（来自旧方案）**
- 视频封面区域根据评论长度自适应，并支持完全关闭。**（来自旧方案）**
- 使用有限范围的 `MutationObserver` 处理评论根容器失效与替换。**（来自旧方案）**

## 17. 成功标准

MVP 成功不以模板数量或动画复杂度衡量，而以以下闭环是否成立衡量：

- 用户能直观发现入口并理解选择模式。
- 用户能稳定选中目标评论且容易退出。
- 无编辑器情况下，生成结果仍具有良好可读性和收藏卡特征。
- 四套模板有清晰差异但保持统一品牌语言。
- 用户愿意保存并在站外分享生成的 PNG。

后续是否投入 AI、动态导出和社区功能，应由上述行为数据和用户反馈决定。
